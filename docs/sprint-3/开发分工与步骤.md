## 注释怎么读：每个类、每个方法第一行都写明 “哪个 PR、谁实现、谁审核”

```java
/**
 * 【PR s3-r3-profile-picture-preview】实现：Sixian ｜ 审核：Stella
 * 【Sprint 3 · US20 #68】主负责人：Sixian。
 * 做什么：像预览图片卷轴一样生成头像的信息预览。
 * 对接/验证：复用 ScrollPreviewRenderer 的图片渲染；界面在 Yuhan 的 ProfilePictureScreen。
 */
```

1. **第一行 `【PR 分支名】实现：A ｜ 审核：B`**：这段代码放在哪个分支的 PR 里、由 A 写、B 审核。
2. **`【Sprint 1/2 已完成 · 本轮不改】原作者：A`**：以前的代码，本轮不动，需要修改先联系原作者。
3. **类注释开头的 `【分工】`**：本文件涉及哪些 PR。
4. **主负责人 / 做什么 / 对接/验证**：谁维护和解释；这一段负责什么；依赖谁的方法、完成后检查什么。
5. 测试方法同样有第一行标记，提 PR 时测试跟着对应的生产代码一起提交。

## 看代码前，先认识新增的结构

| 位置 | 新增 / 变化 | 负责人 |
| --- | --- | --- |
| `model/User.java`、`repository/file/FileUserRepository.java` | 头像字段与 Base64 持久化、向后兼容 | Henry |
| `service/ProfilePictureService.java` | 头像上传校验（扩展名+内容、大小、覆盖、访客） | Stella |

## 每个人从哪里开始

下列路径都以 `app/src/main/java/org/example/` 为起点。

### Henry：US19 的模型与存储（+ CI）

1. `model/User.java`：加 `profilePicture`、`profilePictureFormat`、`NO_PICTURE`；9 参数构造方法（7 参数委托），
   `hasProfilePicture`、`getProfilePicture`（拷贝）、`getProfilePictureFormat`、`withProfilePicture`。
2. `repository/file/FileUserRepository.java`：读写 Base64 头像；读没有 picture 字段的旧快照。
3. 确认 Jenkins 覆盖率门槛仍然满足。

**交给队友的结果：** Stella 调用 `withProfilePicture`；Sixian 读取 `getProfilePicture`；Yuhan 显示状态。
**自己演示：** 上传头像后重启仍在；旧 `users.properties`（没有 picture 字段）照常读取。

### Stella：US19 的业务校验

1. `service/ProfilePictureService.java`：`checkSource`（路径/扩展名/大小）、`setProfilePicture`（内容魔数确认真图片、覆盖、访客）。

**交给队友的结果：** Yuhan 的头像页面调用 `checkSource` 和 `setProfilePicture`。
**自己演示：** `.txt` 改名成 `.png` 被拒；上传新头像覆盖旧头像；访客被拒。

### Sixian：US20 的预览与打开

1. `service/ScrollPreviewRenderer.java`：抽出 `appendImageDetails`。
2. `service/ProfilePictureRenderer.java`：`render(user)`。
3. `service/ProfilePictureViewer.java`：`open()`（复用 FileOpener，不改计数）。

**交给队友的结果：** Yuhan 的头像页面调用 `render` 和 `open`。
**自己演示：** 预览显示 `Image size: W x H pixels`；打开头像不改变任何计数；没有桌面时显示原因。

### Yuhan：US19 + US20 的界面

1. `ui/ProfilePictureScreen.java`：上传/状态/预览/打开。
2. `ui/AccountScreens.java`：资料菜单接入头像页面、资料页显示状态。
3. `ui/ConsoleUi.java`、`App.java`：接线。

**交给队友的结果：** 把三个人的服务连成用户能走的完整流程。
**自己演示：** 只用编号走完上传、预览、打开；非图片扩展名立即提示并重问；资料页显示 Picture 状态。

## 共享函数具体怎样合作：预览头像的例子

1. Henry R1 在 `User` 加 `getProfilePicture()`/`getProfilePictureFormat()`，Stella 审核。
2. Sixian R2 在 `ScrollPreviewRenderer` 抽出 `appendImageDetails`，并写 `ProfilePictureRenderer.render`，Stella 审核。
3. Yuhan R3 在 `ProfilePictureScreen.preview` 中：`render(user)` 显示信息 → 若有头像给出 “Open in default app”。
4. Sixian 不改资料菜单；Yuhan 不改渲染规则。
5. 合并后一起验证：上传 png → 资料页显示 added → 预览显示 6x4 像素 → 打开不改变下载/上传计数。

## 哪些文件最容易冲突，怎样避免

| 共享文件 | 谁先处理 | 谁随后接入 |
| --- | --- | --- |
| `User.java`、`FileUserRepository.java` | Henry R1（唯一修改人） | Stella、Sixian、Yuhan 只调用 |
| `ScrollPreviewRenderer.java` | Sixian R2（唯一修改人，同一原作者） | ProfilePictureRenderer 调用 |
| `AccountScreens.java`、`ConsoleUi.java`、`App.java` | Yuhan R3 | 其他人只写自己的服务/页面类 |

可以同时开发不同文件。确实要改同一段时，先在群里说明“我准备修改哪个方法”，让另一人先合并，再同步最新版本。
