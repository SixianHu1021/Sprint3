## 注释怎么读：每个类、每个方法第一行都写明 “哪个 PR、谁实现、谁审核”

```java
/**
 * 【PR s2-r2-scroll-edit-stats】实现：Stella ｜ 审核：Sixian
 * 【Sprint 2 · US10 #11】主负责人：Stella。
 * 做什么：上传者管理自己的卷轴：查看、改名、替换文件、删除。
 * 对接／验证：登录检查调用 Yuhan 的 requireUser；格式判断调用 Sixian 的 FileFormat.detect。
 */
```

1. **第一行 `【PR 分支名】实现：A ｜ 审核：B`**：这段代码放在哪个分支的 PR 里、由 A 写、B 审核。
   分支名与 [执行手册](Sprint2执行时间线与Git流程.md) 的 PR 总表（P1–P13）一一对应。被两个 PR 修改的方法会写两段。
2. **`【Sprint 1 已完成 · 本轮不改】原作者：A`**：Sprint 1 的代码，本轮不动，需要修改先联系原作者。
3. **类注释开头的 `【分工】`**：本文件涉及哪些 PR，一眼看出这个文件会被谁改。
4. **主负责人 / 做什么 / 对接／验证**：谁维护和解释；这一段负责什么；依赖谁的方法、完成后检查什么。
5. 测试方法同样有第一行标记，提 PR 时测试跟着对应的生产代码一起提交。

## 每个人从哪里开始

下列路径都以 `app/src/main/java/org/example/` 为起点。

### Henry：US03 修改资料、US16 联系方式唯一（+ CI）

1. `repository/UserRepository.java` → `file/FileUserRepository.java`：`findByEmail`（忽略大小写）、`findByPhone`（忽略分隔符）。
2. `service/ContactValidator.java`：`email()` 小写化、`phone()` 字符检查、`requireUnique()` 说明哪个字段重复。
3. `service/AccountService.java`：`create()` 的新顺序；`updateProfile()`、`changePassword()`；`requireAdmin()` 改 public。
4. `ui/AccountScreens.java`：`createAccount()`（从 Sprint 1 ConsoleUi 迁来）、`profile()` 页面。
5. `app/build.gradle`、`Jenkinsfile`：覆盖率门槛和 Code Quality 阶段。

**交给队友的结果：** Stella 可以调用 `requireAdmin()`；Yuhan 在 R4 直接调用 `AccountScreens`。
**自己演示：** 修改资料（回车保留）、用他人邮箱修改被拒绝、修改密码后旧密码登录失败；注册时用大写的已有邮箱被拒绝；Jenkins Stage View。

### Yuhan：US13 编号菜单、US14 输入提示、US15 隐藏密码

1. `ui/ConsoleIO.java`：`askRequired()` 空白立即重问；`error()` 统一 `Error:`；`password()` 隐藏/回退/警告。
2. `ui/Menu.java`：`select()` 的数字、别名、越界、非数字；`runOnce()` 捕获错误后留在菜单。
3. `service/Validation.java`：三种具体消息。
4. `ui/ConsoleUi.java`：`mainMenu()` 编号规则（1 永远是浏览，0 永远是退出；会员/管理员共用 1–5）；`addHidden()`。
5. `App.java`：`ConsoleIO.system` + `ScrollEditService`。

**交给队友的结果：** 其他三人的页面只用 `ConsoleIO` 和 `Menu`，不需要自己处理 Scanner 或错误格式。
**自己演示：** 只输入数字走完流程；输入 9、abc、空行均提示并重新显示菜单；用 `app/build/install/app/bin/app` 登录时密码不显示；
在 IDE/Gradle run 中显示警告。

### Stella：US10 编辑/删除自己的卷轴、US12 统计（+ 模型/存储、README）

1. `model/DigitalScroll.java`：`fileFormat`、`withName`、`withContent`（上传次数 +1）、`withRecordedDownload`。
2. `repository/file/FileScrollRepository.java`：`format` 持久化、`deleteById`、原位替换。
3. `service/ScrollEditService.java`：`requireOwned()` 是关键——先登录、再找到、再比对上传者。
4. `service/StatisticsService.java`：`report()` 先 `requireAdmin()`。
5. `ui/MyScrollsScreen.java`、`ui/StatisticsScreen.java`。

**交给队友的结果：** Sixian 的格式和下载依赖模型的 `fileFormat` 和 `withRecordedDownload`。
**自己演示：** 我的卷轴列表只显示自己的；改名；替换为 PDF 后格式和上传次数变化；删除需确认；不能删别人的；
管理员统计页面（下载、替换后数字变化）；管理员用编号选择角色创建 MEMBER/ADMIN。

### Sixian：US06 筛选、US17 按格式预览、US18 排序

1. `service/FileFormat.java`：扩展名优先 → 魔数 → 文本 → unknown。
2. `service/ScrollFilter.java`、`SortOrder.java`、`ScrollQueryService.java`。
3. `service/ScrollService.java`：`upload()` 记录格式；`download()` 补扩展名、拒绝文件夹。
4. `service/ScrollPreviewRenderer.java`：五种预览。
5. `ui/BrowseScreen.java`：列表标题显示排序与筛选；预览页可直接下载。

**交给队友的结果：** Stella 的替换文件调用 `FileFormat.detect`；Yuhan 的主菜单第 1 项调用 `BrowseScreen.show()`。
**自己演示：** 按上传者、ID、名称、日期分别筛选；无结果提示；清除；按下载次数排序（标题变化）；
预览 txt / png / pdf / zip；下载到无扩展名路径后自动变为 `.pdf`。

## 共享函数具体怎样合作：编辑卷轴的例子

1. Stella R1 在 `DigitalScroll` 加 `withContent(bytes, format)`，Sixian 审核格式字段。
2. Sixian R1 写 `FileFormat.detect(fileName, bytes)`，Stella 审核。
3. Stella R2 在 `ScrollEditService.replaceContent()` 中：`requireOwned` → 读取文件 → `FileFormat.detect` → `withContent` → `save`。
4. Stella 不改格式识别规则；Sixian 不改所有者检查。
5. 合并后一起验证：上传 txt → 替换为 pdf → 浏览列表格式变为 pdf → 管理员统计上传次数为 2。
